## 核心差异

| 项目 | 本地 | 组员仓库 |
|---|---|---|
| 数据 | 原作者缩小版 2527 张；排除 6 张跨标签像素相同图片 | README 使用 TrashNet/Kaggle；划分脚本没有冲突排除和近重复分组逻辑 |
| 划分 | 相似候选分组不跨集合，1766/375/380；正式清单含像素哈希及 group_id | 两次分层随机划分约 70/15/15；新增 CSV 清单及防覆盖；仓库未提交实际清单 |
| 类别顺序 | cardboard, glass, metal, paper, plastic, trash | 文件夹按字母排序，预期相同；融合时仍应校验 checkpoint 中映射 |
| ResNet18 分类头 | Linear(512, 6) | Linear(512,256) → ReLU → Dropout(0.4) → Linear(256,6) |
| 微调 | 分类头 3 轮，layer4+分类头 7 轮；从最佳分类头模型进入微调 | frozen 分支只训练分类头 10 轮；finetune 分支解冻 layer3+layer4，20 轮 |
| 微调初始化 | 第二阶段读取本次最佳头部 checkpoint | finetune 直接从 ImageNet 建模，没有读取 frozen 分支 checkpoint |
| 优化器 | AdamW，头 1e-3，layer4 1e-4 | Adam；微调 backbone 1e-4，头 1e-3，ReduceLROnPlateau |
| 损失 | 普通交叉熵 | frozen 普通交叉熵；finetune 按训练类频次加权交叉熵 |
| 增强 | 基础随机裁剪+翻转；光照、模糊、组合单独对照 | 基础方案已经包含亮度/颜色扰动和旋转；V2 加强颜色旋转并加入自动对比度；没有 GaussianBlur |
| 验证预处理 | Resize(256)+CenterCrop(224) | Resize((224,224))，直接改变长宽比 |
| 最佳模型 | 验证 Macro-F1 | 验证准确率 |
| 复现 | 固定 seed、配置、划分哈希、逐轮 CSV | frozen 分支新增种子控制；finetune 分支没有同等设置或完整实验日志 |
| 评估 | 清晰/变暗/模糊验证比较；测试集未使用 | 测试评估、混淆矩阵、错误图片、Grad-CAM；已有测试报告 |
| 展示 | Notebook 和报告图 | Streamlit 多页界面、上传预测、热力图、案例展示 |

本地 baseline 验证准确率 90.67%；外部页面写有 92.35% 验证和 90.79% 测试准确率。数据划分、预处理、训练预算、分类头、选择指标都不同，不能据此判定优劣。外部仓库没有提交权重、实际划分清单和完整训练配置，当前不能独立复现并核验这些数值。

## 相对上游的实际文件差异

本次两个快照仅有以下四个受跟踪文件内容不同：

1. `src/data_split.py`：图片文件排序、写出划分 CSV、拒绝覆盖已有划分；移除自动删除旧划分目录。
2. `src/model_transfer.py`：约束冻结模式，保持骨干 eval，检查可训练参数和 BatchNorm 运行统计。
3. `src/train_transfer.py`：固定随机种子、DataLoader generator、检查优化器只包含分类头、逐轮验证 BN 统计不变。
4. `src/evaluate.py`：没有错误预测时提前返回，避免绘图异常。

其余已跟踪文件与本次上游快照一致，包括 `model_finetune.py`、`train_finetune.py`、`transforms.py`、Grad-CAM、Streamlit 页面、README、分类报告和预测 NPZ。它们可以作为已有资源利用，但不能直接把这些已有方法、功能或原有结果描述为本组独立新增成果。新增代码改动也不意味着旧指标已经在修改后重新测得。

## 融合前需要处理的问题

- **演示路径错误**：`app/pages/1_🔍_Demo.py` 的 PROJECT_ROOT 只向上一级，得到 `app/`；后续查找 `app/src` 与 `app/models`，实际应定位仓库根目录。仓库本身也未包含权重，不能直接开箱预测。
- **权重不直接兼容**：本地单层头与外部两层头的 state_dict 键和形状不同，另有 num_classes/class_to_idx 等字段差异。需要统一建模和加载接口；新分类头要训练，不能将不匹配层静默忽略后视为完整加载。
- **冻结 BN 问题**：frozen 分支已有修复；finetune 的 `train_one_epoch` 仍执行全模型 `model.train()`，会更新 layer1/2 等冻结部分的 BatchNorm 统计量。应只让计划训练的层及头进入 train 模式。
- **多因素混杂**：外部 frozen 与 finetune 同时改变解冻层、增强、加权损失、轮数和调度器，不能把全部提升归功于某一项。
- **结果标签与内容不同步**：README 仍写最佳 frozen 78.36% 且微调待做，应用页展示 finetune 结果。evaluate 的报告标题固定写 Frozen，即使评估的是 finetuned。应用分数是代码内写死的值，需要改为读取对应运行结果。
- **Grad-CAM 的定位**：用于辅助观察，不能仅凭几张热力图就证明不存在背景依赖。页面中的绝对结论需要收敛。融合本地中心裁剪预处理时，也应让热力图叠加到相同裁剪图像上。
- **测试使用历史**：外部流程已有测试集评估和错误诊断。融合后先核对实际划分清单、已训练 checkpoint 及训练/调参使用记录；不同划分下的现成模型可能见过本地 test 图片，不能直接视为独立最终测试。保留探索性结果标记，必要时准备新的独立评估集。

## 建议融合路径

1. 保留本地原有四组实验和结果，统一使用经过审计的数据和固定类别映射。
2. 如果继续以抗光照/模糊为项目主线，先保持同一个网络、优化器和训练预算，完成本地 baseline/light/blur/both 的多种子验证。
3. 优先新增“仅类别加权”和“类别加权+组合增强”两组，权重只用训练集计算；固定同一 Macro-F1 选模规则。这对应少数类识别这一可解释问题。
4. 两层分类头、layer3+layer4 解冻作为独立可选因素，逐项验证；不要一次把所有改动叠加，再宣称某一模块有效。
5. 把错误案例图和 Grad-CAM 接到统一的验证集预测上。将展示界面接到本地 checkpoint/预处理，增加原图、变亮/变暗、模糊及改进前后的并排预测；指标从文件读取。
6. 统一 run 配置记录分类头类型、解冻层、loss、增强、seed、轮数、类别映射、划分哈希、预处理和代码版本。方案确定且评估集独立性确认后，再做最终测试。
